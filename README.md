# Project Bedrock — InnovateMart EKS Deployment

Production-grade microservices platform on **Amazon EKS**, provisioned with Terraform and deployed via GitHub Actions. Deploys the AWS Retail Store Sample App with a managed AWS data layer (RDS MySQL, RDS PostgreSQL, DynamoDB), secure developer access, CloudWatch observability, and an event-driven S3→Lambda extension.

## Architecture

See `architecture-diagram.svg`. In short:

- **VPC** (`project-bedrock-vpc`, 2 AZs) with public subnets (ALB + NAT) and private subnets (EKS nodes + RDS).
- **EKS** (`project-bedrock-cluster`, v1.34) with a managed node group, control-plane logging, and the CloudWatch Observability add-on for container logs.
- **Retail Store app** in the `retail-app` namespace; `ui` exposed via an **ALB** managed by the AWS Load Balancer Controller.
- **Managed data layer:** catalog→RDS MySQL, orders→RDS PostgreSQL, carts→DynamoDB. DB security group only allows traffic from the EKS node SG; credentials live in **SSM Parameter Store**.
- **Developer access:** `bedrock-dev-view` IAM user with console `ReadOnlyAccess`, `s3:PutObject` on the assets bucket, and a Kubernetes `view` (read-only) RBAC binding via an EKS access entry.
- **Serverless:** uploads to `bedrock-assets-alt-soe-025-3228` trigger `bedrock-asset-processor`, which logs `Image received: <filename>` to CloudWatch.
- **CI/CD:** GitHub Actions runs `terraform plan` on PRs (posted as a comment) and `terraform apply` on merge to `main`.

## Deployment guide

### Prerequisites
Terraform >= 1.5, AWS CLI, kubectl, helm; AWS credentials with admin for the initial apply.

### 1. Remote state
```bash
aws s3 mb s3://bedrock-tfstate-<unique> --region us-east-1
aws s3api put-bucket-versioning --bucket bedrock-tfstate-<unique> \
  --versioning-configuration Status=Enabled
# uncomment + edit the backend "s3" block in terraform/versions.tf
```

### 2. Provision infrastructure
```bash
cd terraform
cp terraform.tfvars.example terraform.tfvars
terraform init
terraform plan
terraform apply
```

### 3. Connect kubectl
```bash
aws eks update-kubeconfig --name project-bedrock-cluster --region us-east-1
```

### 4. Deploy the app
```bash
cd ../kubernetes
kubectl apply -f 00-namespace.yaml
kubectl apply -f 01-dev-view-rbac.yaml
kubectl apply -n retail-app -f https://github.com/aws-containers/retail-store-sample-app/releases/latest/download/kubernetes.yaml
kubectl apply -f 02-ingress.yaml
```

### 5. Get the store URL
```bash
kubectl get ingress -n retail-app
```

### 6. Grading JSON
```bash
cd ../terraform
terraform output -json > ../grading.json
```

### CI/CD trigger
- PR touching `terraform/**` → posts a `terraform plan`.
- Merge to `main` → runs `terraform apply`.
- Secrets required: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`.

## Security highlights

- **No secrets in git.** DB passwords generated by Terraform, stored in SSM `SecureString`; `terraform.tfvars` is gitignored.
- **Least-privilege** `bedrock-dev-view`: console ReadOnly + a single `s3:PutObject`, read-only Kubernetes via the `view` role.
- **Network isolation.** RDS in private subnets; DB SG only accepts traffic from the EKS node SG.
- **Private buckets.** The assets bucket blocks all public access.

## Deployment status

The complete infrastructure, Kubernetes manifests, Lambda code, CI/CD pipeline, and architecture diagram are implemented here and are deployable with the commands above. A live AWS deployment was not provisioned for grading because AWS credits were unavailable at submission time. The Terraform is structured to `apply` cleanly given valid credentials.
